# Stage 4e on Kaggle

Kernels generated by `build_kernels.py` from [`../../stage4e_imbalance.ipynb`](../../stage4e_imbalance.ipynb) ([plan](../../stage4e_plan.md)). Only the settings cell differs between kernels. Run them in order. The two `e1` kernels can run at the same time.

| Kernel | Work | Inputs | Time |
|---|---|---|---|
| `dr-s4e-e0-quick` | Quick test of every code path (toy sizes, folder `stage4e_quick_test`). Downloads the images and caches them as `aptos512.zip`. | `dr-stage4-outputs`, `dr-stage4-weights` | ~25 min (T4) |
| `dr-s4e-e1-focal` | `focal_s42`, `focal_s43`, `focal_s44`, `ce_s42_k` | `e0-quick` | ~2.5 h (T4) |
| `dr-s4e-e1-cb` | `mse_cb_s42`, `mse_cb_s43`, `mse_cb_s44`, `mse_s42_k` | `e0-quick` | ~2.5 h (T4) |
| `dr-s4e-e2-final` | No training. Tables, paired bootstrap, prediction check, control check, Mann-Whitney, retina Grad-CAM. | `e0-quick`, both `e1`, both datasets | ~15 min (CPU) |

Datasets (private):

- `dr-stage4-outputs`: the six Stage 4 Colab runs' `config.json` and `outputs.npz` (`ce_s42-44`, `mse_s42-44`).
- `dr-stage4-weights`: `mse_s42_best_val_weights.pt`, for the Grad-CAM check.

```bash
python build_kernels.py <kaggle username>              # regenerate after editing the notebook
kaggle kernels push -p dr-s4e-e0-quick                 # Kaggle CLI >= 2.0 for the T4 machine shape
kaggle kernels output <user>/dr-s4e-e2-final -p out    # results in out/dr-grading/stage4e/
```

If an `e1` kernel stops at the time guard, add its own slug to its `kernel_sources` and push it again. Finished runs are never retrained, and an interrupted run resumes from its last checkpoint.

**Local CPU smoke test (done before the first push):** the code cells were run with fake images at 64 px, 2 epochs, plus the real Stage 4 outputs and weights. Every code path ran, and the reused Stage 4 arms reproduced `results/stage4/results_per_seed.csv`. A second, analysis-only pass restored the finished runs from the first pass's output.
